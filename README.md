# 灯火之外 · 主持

独立的 SillyTavern 前端扩展。电脑和手机本机酒馆使用同一份扩展，不需要额外 DSH 服务、酒馆助手或服务器插件。

在主持窗口讨论当前游戏，读取当前酒馆聊天，查阅游戏资料；回复可以编辑后填入酒馆输入框，最后由玩家自己发送。

## 安装

需要 SillyTavern 1.14.0 或更新版本。使用酒馆的「扩展 → 安装扩展」填写 `https://github.com/shiruku-kodomo/lantern-host-extension`，或解压安装包，将 `lantern-host-extension` 文件夹放到酒馆的 `data/default-user/extensions/` 中（多用户时使用自己的账号目录），刷新酒馆。

私有仓库需要 GitHub 访问权限；手机可以使用 ZIP 文件夹安装，不需要运行构建命令。安装包中的 `manifest.json` 应直接位于扩展文件夹内，避免多套一层目录。

从酒馆输入框旁的扩展菜单，或扩展设置中的「灯火之外 · 主持」打开工作区。

## 使用

1. 在酒馆打开角色和聊天。
2. 打开主持窗口的「模型与提示词」，填写接口地址和 API Key，点击「连接并获取模型」。选择或手动填写模型，点击「保存并使用」。可以保存多份连接配置；切换配置后点击「保存并使用」才会改变当前主持模型。
3. 在「对话」中发送消息。点击消息下的铅笔，在原位置编辑，再选择「取消」或「发送」。编辑与重试都会建立可切换的版本分支，旧回复和后续对话保留，不会复制到输入框重复追加。主持连接和提示词对所有聊天生效；正文继续使用酒馆原来的连接。
4. 在「资料」浏览、搜索原策划和游戏内容，选择需要的原文并「附加到对话」。支持导入 Markdown、TXT、JSON。附加资料会送到当前选择的主持模型。
5. 回复下点击「交给酒馆」，编辑预览，再选择「追加到输入框」或「填入／替换输入框」。扩展不会点击酒馆的发送按钮。

手机默认全屏；顶部「−」收起为浮动按钮，点击恢复。电脑可以拖动窗口右下角调整大小，或切换全屏。

回复和 Markdown 资料支持标题、列表、表格、引用、行内代码和代码块。资料可切换「查看原文」。附加和交接使用原文，不使用排版后的 HTML；外部图片不自动加载。

## 上下文压缩

在连接中设置模型的实际「上下文容量 Token」，默认填写 128000，可按所用模型修改。输入用量采用保守估算，显示为估算值；最大回复 Token 会单独预留。自动压缩默认开启，在预计输入达到可用容量的 80% 时触发，也可点击「压缩较早对话」或输入 `/compact`。

压缩使用当前主持连接生成摘要，保留近期对话，原始消息和全部分支仍随存档保存。切换到不同版本后，摘要只在它对应的消息前缀中生效；取消、失败或无效摘要不会删除原始记录。资料原文和酒馆当前上下文不会被自动删减。摘要可能遗漏细节，正式数值判定仍须在后续工具中读取原始规则和存档数值。

## 主持指令

输入 `/` 可用鼠标、触摸或方向键选择指令，回车／Tab 补全。指令在主持工作区执行，不会送进酒馆命令框。

| 指令 | 行为 |
| --- | --- |
| `/plan` 或 `/plan 任务` | 进入计划模式；附带任务时立即向主持请求计划。`/plan off` 退出。 |
| `/chat` | 回到普通对话模式。 |
| `/goal 目标` | 保存本局目标，后续主持对话带入这个目标。 |
| `/goal status` | 查看目标；也支持 `pause`、`resume`、`done`、`clear`。 |
| `/compact` | 压缩较早的主持对话。 |
| `/status` | 查看模型、模式、目标和上下文估算。 |
| `/model` | 打开模型设置。 |
| `/help` | 查看当前可用指令。 |

在「模型与提示词 → 主持指令」中调整指令开关、新建提示词指令并手动保存。自定义指令只展开提示词，`{input}` 表示指令后的文字，不执行 JavaScript 或系统命令。指令设置对全部存档生效；模式、目标和目标状态随当前聊天保存。目标不会自行启动工具或无人值守循环，多 Agent 执行仍属于后续阶段。

## 记录与恢复

主持会话、输入草稿、交接草稿、所选资料和未完成回复保存在当前聊天的 `chat_metadata.lantern_host`。本地 IndexedDB 另存待同步副本。不同账号、角色和聊天的记录分开；切换酒馆聊天时自动切换。当前选中的回复版本、角色描述、性格、场景和玩家 Persona 可作为上下文带入。

保存会读回核对。出现「重试保存」时，内容仍留在窗口和本地副本；请重试或「导出本局」，不要清理浏览器数据。其他窗口已经修改同一记录时会停止覆盖，先导出并刷新核对。不同设备要使用同一份酒馆存档文件才能共享已同步记录；未同步的本地副本只在该浏览器内。

连接配置保存在酒馆账号设置中，API Key 与酒馆设置一同保存在本机。请勿分享整份酒馆设置；本局导出文件不含连接配置和 API Key。

## 当前阶段

本版实现扩展入口、独立主持对话、上下文连接、记录恢复、资料工作区及人工确认交接。资料包保留原策划原文，其中旧桌面页面的描述属于历史方案；扩展形态以本 README 和用户确认的第一阶段方案为准。

多 Agent 分派、真实骰子工具、数值结算、物品和情报写入尚未接入。主持默认提示词会明确这一点。资料搜索是本地原文搜索，不是已完成的自动规则检索系统。后续按原策划与已确认的主持分工接入，不用附件世界书替代策划。

## 开发与验证

运行时无 npm 依赖，不加载外部 CDN，不修改酒馆正文连接。`src/bridge.js` 连接酒馆；`src/provider.js` 调用模型；`src/sessions.js` 管理记录同步；`src/documents.js` 管理资料。

```sh
npm test
npm run pack
# 仅维护资料包时需要原始策划目录；安装使用不需要执行：
node scripts/build-content.mjs /path/to/3.策划文档
```

自动化验证记录见 [VALIDATION.md](VALIDATION.md)。真实手机触摸、输入法和不同浏览器的最终设备验收须与浏览器视口模拟结果区分。

集成脚本 `tests/browser.mjs` 需要 Playwright，并要求显式设置 `TAVERN_URL` 指向独立验收数据目录的酒馆实例；不要把它指向正在游玩的存档。可用 `PLAYWRIGHT_MODULE`、`CHROME_PATH` 指定本地浏览器依赖位置。
