# 灯火之外 · 主持 0.3.8

0.3.7：主持只做任务、阶段与判定，正文负责具体演绎。收起、关闭面板和Esc都保持运行，停止使用独立按钮；只保留主持、判定、分析、情报四种Agent。当前选中正文作为已发生剧情直接承接，已有判定和数值以主持保存为准。战斗只需比较参数，不再填写五轮动作。

电脑与手机本机 SillyTavern 共用的标准前端扩展，无需 DSH 服务或服务器插件。模型、Agent 提示词和功能设置全局共用；人物、资源、物品、任务和情报按酒馆聊天与历史分支隔离。正文继续使用酒馆当前连接，玩家手动发送。

## 使用

正式角色建档由扩展按当前输入的明确命中执行：它读取资料包原文、固定版本化面板和来源，再写入本局数据库；后续轮次复用同一实体。只有过渡角色或玩家新捏出的角色需要模型调用 ensure_entity。普通执行阶段主持拥有全量机制和骰子权限，计划阶段与已提交检查点保持只读。

要求主持扮演正式角色、决定玩家身份并给出三个任务的开场，优先使用 `prepare_opening` 批量保存：原文角色、初始知情自动就绪，模型仅补齐玩家与任务候选。接口分段提交时复用已保存部分，候选保存并真实投骰后进入汇总，不再分派重复建档；三个任务仍需玩家选择后才能接取。

主持判断适合连续处理一次调查或一个五次交锋块时，使用相应执行工具预先声明条件，再由脚本完成真实判定、变化和落档。复杂场景仍可按需分派Agent及使用单项机制；专责Agent只接收本次任务，正文文风保留给主持交接和酒馆生成。

1. 打开酒馆聊天，点击常驻“灯”悬浮入口。入口可拖动，关闭／收起工作区后仍保留。
2. 在模型设置填独立接口地址与API Key，连接获取模型列表，选择后手动保存。支持多份配置，不改变酒馆正文连接。
3. 普通模式发送开场和行动。主持按依赖分派判定、分析、情报任务，使用真实工具查询和批量结算；正式角色按正式资料建档，玩家捏出的过渡角色先由 `ensure_entity` 固定生成定义和实体，再登记情报，生成内容保留玩家输入来源。
4. `/plan 任务`生成计划卡，提供执行、修改、取消。确认前只查询整理，不投正式骰子或改变游戏状态。
5. 回复前按时间显示简短中文进展与单层工具分组，查看实际任务、关键数值和提交状态；不显示JSON或嵌套详情，新进展不重置分组展开状态与阅读位置。只展示接口明确提供的公开摘要，不编造隐藏思考。
6. 点击“交给酒馆”预览和编辑，交接包含该分支对应的玩家原话及主持结果。选择追加或替换输入框，由玩家自己发送。

电脑支持调整大小和全屏；手机默认全屏，适配可视窗口高度及横竖屏。实体手机测试范围见VALIDATION.md。

## 真实机制

骰子由 `src/exact.js` 调用浏览器 `crypto.getRandomValues()` 与拒绝采样生成，不由LLM填写点数。`src/game-db.js` 先事务落库再返回。同ID、同参数重试复用结果；改变已投参数报 CHECK_CONFLICT。

`src/mechanisms.js` 注册实际操作，覆盖关系、提议、战斗、形态、技能、状态、物品、成长、任务、时间、情报、合作、叙述及世界阶段。Agent没有任意数据库写入和代码执行权限。机制映射及边界见RULE_COVERAGE.md。

内容索引包含原文ID、固定实体标识、别名、哈希和解析后的面板字段。已有数值从正式字段或本局数据库读取；字段缺失明确失败，允许补齐的参数使用generated定义保存，不冒充正式资料。玩家生成角色通过 `ensure_entity` 原子式完成定义和实体建档，后续情报引用同一实体ID。HP/MP保存精确分数，显示取整不写回资源。最终Boss阶段突破、最终战果和特殊MP承接分别处理。

## 存档与世界书

IndexedDB是正式本局数据库，独立记录局、分支、人物、内容、物品、任务、情报、骰子、事件、计划和运行步骤。完整事件事务提交，每轮归档原话、工具过程、前后状态、结果和下一停点。底部可查看每轮存档或导出。

新建原生聊天建立新局；回到旧聊天恢复旧局，改名保留绑定。修改历史行动建立隔离状态分支；重试已结算回复沿用原结果，不重复扣除或发奖。

酒馆原生文件接口保存备份，SHA256读回核对后才更新聊天元数据索引。备份包含历史分支，大文件分块。旧记录先迁移和核对备份，再精简元数据。失败保留本地内容和重试队列，世界书同步重试不会重新结算。其他浏览器恢复依赖同一酒馆服务器的聊天和备份文件。

首次登记有效情报后，建立独立本局世界书。存在聊天绑定的初始书时复制快照，否则创建补充书；保留原全局和角色世界书。插件只更新带自身标记的“本局角色已知情报”，保留其他手工条目。

托管条目固定蓝灯 `constant=true`、System @D `position=4, role=0`、深度9999，写后核对并刷新缓存。设置ignoreBudget避免被世界书子预算静默筛掉，但仍真实占用模型总上下文。

全部人物的已知情报按人分组提供正文，标明字段、可信状态与来源；人物之间通过正文中的对话、阅读和目击承接知情，不再单独调用角色Agent。核心保留依正式实体来源，生成内容仅有名字不算正式；失效过渡信息可从投影清理，数据库历史及未完成任务依赖保留。丢物证不等于遗忘。新局、旧局和历史分支分别恢复对应世界书，丢失文件可重建。

## Agent 设置、上下文与指令

设置页的每个 Agent 都提供一个直接可编辑的提示词文本框。保存后，该文本作为对应 Agent 的提示词使用；各Agent共享已注册的机制和骰子工具，计划阶段只读；已取消货币、路线及移动前置校验。

`gpt-6.1-sol`自动映射500k×95%=475k有效窗口，接口限制和手动覆盖分别记录。百分比只统计输入，回复预留单列；有usage记录实际值，否则标估算，Agent分别计量。

自动压缩较早对话和过程摘要，保留原始历史；超长历史分批处理。摘要不能替代正式数值、内容定义、骰子和知情记录。

| 指令 | 功能 |
| --- | --- |
| `/plan 任务` | 计划卡；`/plan off`退出 |
| `/chat` | 普通模式 |
| `/goal 目标` | 目标；支持status、pause、resume、done、clear |
| `/compact` | 压缩早期对话 |
| `/status` | 查看本局状态 |
| `/model` | 模型及全局设置 |
| `/help` | 指令列表 |

自定义指令只展开提示词，不执行代码。API Key随本机酒馆账号设置保存，不进入游戏导出和GitHub发布包。

## 开发与验证

运行时无npm依赖、无外部CDN。开发运行 `npm ci`、`npm test`、`npm run pack`。维护资料时 `npm run build` 需要原策划目录。

- VALIDATION.md：实际验收与设备边界。
- RULE_COVERAGE.md：机制到执行工具的对应。
- BATTLE_TESTS.md：用户指定的初始柠彩莲基础战斗实测；不冒充完整Agent战术对局。
- DICE_PROOF.md：零LLM骰子、存储和重试核验。

集成测试必须将TAVERN_URL指向独立QA酒馆。确定性HTTP模型用于验证协议与真实工具，不代表实际模型在所有游戏情境中的判断质量。

## 0.3.6执行与恢复

高阶开局、调查与战斗工具默认在实际完成后生成事实交接；如需继续角色决策，主持传入 `finish_turn:false`。批量工具明确选择是否结束本轮。生成内容自动保留玩家输入或生成原因作为来源，正式数值继续核验原文。接口分段提交开局时保存有效部分，仅补齐缺项。扩展不设置请求时限，持续等待模型；主动停止、切换聊天或真实连接错误才结束。检查点和既有骰子保留，重试不重复结算。

## 窗口与正文承接

−、×和Esc只隐藏工作区，悬浮入口显示运行、完成、暂停或保存状态；恢复后保持阅读位置。页面被系统暂停或刷新后，点击未完成回复的重试即可沿用检查点和骰子继续；不承诺锁屏后台持续执行。同一聊天正文更新不会打断当前任务，本轮沿用开始时的选中版本，新内容下一轮承接。

正文中的新对话、发现和互动直接作为剧情事实按需登记，不要求额外证明；矛盾的数值不覆盖主持存档。主持报告点数、胜负、任务阶段和所得；动作、对话、内心与战斗过程由酒馆生成。
